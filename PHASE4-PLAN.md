## Commit A: type-compatible sentinels — completed in `8d24dd7`

### The break, stated as a defect

`normalize_artifact_object` (`tui_real_host.rs:1866`) writes two **type-incompatible** tokens:

- `Value::String("<source-identity>")` or `"<source-identity:N>"` over `identity: Option<SourceIdentity>`.
- `Value::String("<modified>")` over `modified: u64`.

Three committed sites require the normalized JSON to deserialize back into typed values **and**
re-serialize byte-identically:

1. `tui_real_walker.rs:592` `parse_library_state` — `from_value::<LibraryState>` then asserts
   `json_value(&state) == *value`.
2. `tui_real_walker.rs:573` `validate_reducer_action` — `from_value::<Action>`.
3. `tui_walker_bundle.rs:394` `validate_live_locales` — `from_value::<skit_ui::Action>`.

The state normalizer reaches the tokens: `normalize_library_json` → `normalize_workflow_artifacts` →
`normalize_add_screen` → `normalize_artifact_object`. So a reducer object holding `Screen::Add` with
one draft **cannot** be parsed back. This is a live defect at `0945263`, latent only because the
smoke walk never presents `Screen::Add` with a draft. A 100-operation walk does.

### The walker-support additions commit A owns

Two pure pieces move to `crates/skit-tui-walker-support/src/`, because `cargo mutants` skips
`#[cfg(test)]` and anything inside skit-cli's test module is mutation-blind:

- **The dense ascending rank allocator.** `assign_sorted(&mut self, ascending: &[u64])` refuses a value
  that is not strictly greater than the current maximum; `lookup(&self, observed: u64) -> Option<u64>`

  source under the coverage gate. As a pure `Value` function, a unit test feeds it a Windows-shaped
  input on Linux.

### The ordering constraint, and why the obvious designs fail

`crates/skit-ui/src/add.rs:391` and `:426` sort drafts with `sort_by_key(|d| Reverse(d.modified))`.
Two designs were proposed and both were rejected by `advisor-opus` on measured evidence.

Rejected, a plain counter in first-observation order: drafts are stored **descending** by mtime and
`normalize_add_screen` iterates them in stored order, so the counter gives the newest draft the
smallest sentinel and **inverts** the ordering. Replay through `validate_reducer_action` then fails
with `"a reducer object does not match its production Action"` whenever
`DraftDeleteOutcome::Changed` lands with two or more surviving drafts, because `replace_draft`
(`add.rs:426`) re-sorts.

Rejected, a gap/midpoint order-maintenance allocator: its output depends on **allocation order**, and
the first allocation runs over `HostObservation.drafts`, which is
`serde_json::to_value(tui_drafts(..))` (`tui_real_host.rs:301-303`) collected straight from
`fs::read_dir` with no sort (`cli.rs:9836-9862`) over `tempfile`-random `skit-new-*` names
(`cli.rs:8906-8909`). Readdir order is not mtime order, so two runs produce different sentinel values
for identical inputs and `main_and_replay_bundles_are_byte_identical` fails. It also underflows
`u64` at the third successor-only insertion, which is the normal case for a descending batch.

**A live defect falls out of that analysis, and it belongs in commit A because it changes stored
bytes: `HostObservation.drafts` has nondeterministic array order** once two drafts exist. It is
latent only because every current contract seeds one draft.

### The replacement vocabulary

**`modified` → a dense ascending rank, allocated from the sorted scan, not from the observation.**

The precedent is already in the file: `PathMap::refresh` (`tui_real_host.rs:1477`) does not trust
observation order for `<draft:N>` either. It re-scans, sorts, then allocates ordinals, and it runs at
the top of both `observe` (`:245`) and `canonical_action` (`:312`), so it always precedes
normalization. Extend that one mechanism:

- In `refresh`, collect the scanned `modified` values, sort **ascending**, and allocate the next dense
  sentinel for each unseen value.
- `normalize_artifact_object` becomes a pure **lookup**. A miss is a hard refusal: it means a
  `DraftSummary` reached an artifact without its file being scanned, which is a walker bug.
- An unseen scan value that is **not strictly greater** than the current maximum is a hard refusal.
  That single rule buys monotonicity, so the dense counter is order-preserving forever, and mtime
  **distinctness** across drafts. Distinctness matters on its own: `sort_by_key` is stable, so two
  drafts sharing an mtime make the product's own draft order nondeterministic and no normalization
  can repair it.

The assumption holds by construction: drafts are created by `tempfile` at wall-clock time
(`cli.rs:8906`), `EditSource` rewrites move mtime forward, `refreshed_draft` (`cli.rs:9893`) reports
the newer mtime, and the `Changed` restore path uses `fs::hard_link` (`cli.rs:9256`), which preserves
the already-registered mtime. If a future seed breaks it, the refusal fires loudly.

**`identity` → a typed sentinel keyed on the `same_file` projection.** Keep the observed `platform`
tag and refuse a missing or unknown tag. Rewrite only the numeric fields:

- unix: `{"platform":"unix","device":0,"inode":i,"change_time_seconds":0,"change_time_nanoseconds":c}`
- windows: `{"platform":"windows","volume_serial_number":0,"file_index":"i","creation_time":c}`
  — `file_index` is `u128` written through `u128_decimal`, so it is a **decimal string**.

`i` comes from a single **global** counter keyed on the `same_file` projection of the observed
identity, so distinct real files never collide across paths and `device: 0` stays safe. `c` is a
sub-generation keyed on `(same_file projection, ctime pair)`.

The key must be the `same_file` projection, **not** the raw identity JSON. `same_file`
(`skit-application/src/lib.rs:129`) compares device and inode only, while the raw JSON also carries
the ctime pair. Keying on raw JSON would give a re-stat after an **in-place write** a new key, a new
`i`, and therefore a sentinel that says "different file" where the product says "same file" — exactly
the case `DraftChanged` exists to report. The ctime sub-generation keeps full `==` inequality visible
without breaking `same_file` equality.

The Windows `file_index` must be a string for a stronger reason than shape fidelity: `u128_decimal`'s
`Encoded` enum is `untagged` and accepts a legacy `u64`, so a number **would** deserialize and would
then fail the canonical `json_value(&state) != *value` check in `parse_library_state`. Assert the
canonical round trip, not only `from_value`.

`<transient:N>` and `<walker-agent-skill-path>` stay as they are. Those sit in `String` fields.

### Fallibility and fixtures

Refusing an unknown `platform` tag makes the artifact normalizer chain **fallible** up to `observe`
and `canonical_action`, which both already return `Result`. That is more churn than revision 1
admitted. It also invalidates the fabricated identity shapes at `tui_real_host.rs:4519-4548`, such as
`{"unix":[7,8,9]}`, which today's shape-agnostic normalizer happily stringifies. Rewrite them to real
`platform`-tagged shapes.

## Commit C0: deterministic real environment before projection

JSON projection cannot repair text that the production renderer has already written into a
`StyledFrameSnapshot`. The frame object, its readable view, and `trace.cast` preserve those bytes.
Do not rewrite rendered cells. Such a rewrite has no field provenance and can change user text,
clipping, wrapping, styles, geometry, and hit evidence.

### C0a: inject only the four proven name-entropy boundaries

Use one low-level raw file-allocation port. It must not return an `Action`, an `Effect`, or a product
outcome. Callers select a closed purpose enum and cannot supply a prefix. Production keeps its
current random behavior. Each fresh `SeededTuiHost` gets a deterministic adapter with an independent
monotone counter for each purpose.

The four C0 allocation points are:

- authored draft `skit-new-XXXXXX.<kind>`;
- draft quarantine `.skit-quarantine-XXXXXX/draft`;
- injected source `.injected-XXXXXX.<suffix>`; and
- launch snapshot `.run-<32hex>.<suffix>`.

Use six lower-case hexadecimal digits for draft, quarantine, and injected-source names. Use 32 for
launch snapshots. Open files with `create_new`. Create private files as `0600` and directories as
`0700` on Unix. An `AlreadyExists` result consumes the candidate and retries. Any other error returns
at once. Checked counter overflow refuses.

Keep lifecycle ownership unchanged:

- `NamedTempFile` owns draft and injected-source cleanup. Draft `keep()` still transfers ownership.
- Quarantine success and mismatch restore remove the directory. Restore failure retains the claimed
  bytes and reports the deterministic path.
- `FileStore` still owns launch locks, identity and hash checks, the `.run-` prefix, the 32-digit
  lowercase stem format, path construction, `create_new`, file/path identity validation, copied
  bytes, source mode, `fsync`, partial-failure rollback, and `PreparedLaunch` drop cleanup. The
  adapter supplies only a typed `LaunchSnapshotStem`, records the store's attempt evidence, and
  selects whether a real `AlreadyExists` result can consume the next walker stem. Production keeps
  its one-attempt collision behavior.
- The injected-source System-versus-entry fallback order stays byte-faithful. The allocation API must
  distinguish a system temp location from a named directory.

Record each walker allocation before Editor, Gate, Launch, or store evidence. Record purpose,
attempt, location kind, raw path, and either success or stable `io::ErrorKind` plus reason. Register
the actual artifact in the one `PathMap` before transcript serialization. Observation and projection
must never consume an allocation counter.

Required contracts use real files and directories: fresh-host reset; independent counters;
`000000` then `000001`; collision without clobber; exact suffix and width; Unix modes; editor
cleanup/keep; quarantine restore/retain; injected gate and launch cleanup; launch bytes, mode,
collision, partial failure, and drop cleanup; transcript order and outcome.
