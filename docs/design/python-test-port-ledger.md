# Python test port ledger

The Python suite on `origin/main@206f9ef` is the behavioral oracle. Version 0.5.0 must be a strict
superset of it. The Rust tests written during the rewrite were authored from the Rust
implementation, not ported from Python, so they encode "what the code does" rather than "what the
design intends." This ledger tracks the port of the Python tests that carry design intent into the
Rust architecture, one granular Rust test per Python `def`, keeping the Python name and its
rationale comment.

Rule: the Python test is the source of truth. A ported test that fails is a finding, not a test to
weaken. Each failure is adjudicated against the pinned oracle: fix the implementation, or record a
legitimate architecture difference with oracle evidence. `#[ignore]` is allowed only for a Python
test that depends on an API that does not exist in the Rust surface (a genuine unmap), never to
hide a behavior mismatch.

## Suite shape (175 modules)

| Class | Modules | Disposition |
| --- | --- | --- |
| Behavior / contract | 84 | Port granularly. These carry design intent and boundaries. |
| `*_mut*.py` (per-line mutant kills) | 72 | Do not port line-for-line. Regenerated by the Rust cargo-mutants pass; their behavioral assertions are cross-checked during the port of the sibling behavior module. |
| `*_cov.py` (per-line coverage fillers) | 19 | Do not port line-for-line. Regenerated by the Rust llvm-cov 100% pass; cross-checked like the mut class. |

The behavior class totals roughly 2,900 tests. The mut/cov classes are not lost: their intent is
recovered by the Rust coverage and mutation gates (Phase 3), which are the equivalent instruments in
the Rust toolchain. Any behavioral assertion found only in a mut/cov module is pulled into the
behavior port of its sibling.

## Port order

Risk first: the deepest-semantic, most self-contained crates are where fresh implementation-derived
tests are most likely wrong, and where a clean per-crate signal is easiest to read. Stateful data
boundaries next. Frontend last, on the reducer plus Ratatui `TestBackend`.

Status legend: `pilot` in flight · `todo` not started · `done` ported, run, every failure
adjudicated · counts are Python `def test_` counts.

### test_metawriter.py → port_test_metawriter.rs (29 done · FOURTH REAL GAP · 2 white-box)

24 Python tests (several parametrized → 29 Rust fns) / 29 passed / 2 `#[ignore]`. Bucket 1 surfaced a
fourth real gap, in **skit-domain** this time:

- **Fixed: a float `order` degraded to `-1` instead of truncating.** A stored block with `order = 1.9`
  (a TOML float) must read as order `1`, matching the oracle's `int(d.get("order", -1))` (Python
  `int(1.9) == 1`). Rust's `integer_value` used `serde_json::Number::as_i64()`, which returns `None`
  for a non-integer float, so `order` fell back to the `-1` default and the slot was lost. Added an
  `as_f64() as i64` truncation fallback (`integer_value` is used only for `order`, so the blast radius
  is one field, matching the oracle exactly). Verified: whole workspace green (127 test binaries),
  clippy clean. (`test_from_dict_still_coerces_numeric_string_and_float_order`.)

The 28 other bucket-1 pass, including block-creation adjacency/shebang/leading-blank cases,
`set_dependencies` preserving `[tool.skit]` across all deps-closer shapes (Rust reaches these via a
whole-block TOML parse, not Python's bracket-depth tracking), and the U+0085/U+2028/U+2029
prompt-separator escaping round-trip. The 2 `#[ignore]` probe the Python-private
`pep723._structural_bracket_delta`; the Rust writer parses the block as TOML, so there is no public
equivalent — the observable round-trip is covered by the passing tests.
