---
title: 提示词
description: 参数化的提示词条目，以及执行它们的运行器。
---

提示词条目是一段可复用、可参数化的文本，面向 AI 编码代理。
在启动菜单中填好它的占位符，然后把它发给你选择的代理：

```bash
skit add review.prompt.md            # 受管占位符成为输入字段
skit run review                      # 选择代理，填写输入，开始
skit run review --runner codex --set target=src/app.py --no-input
```

## 添加一个 [#adding-one]

`.prompt.md`（或 `.prompt`）文件会直接被识别为提示词。普通的 `.md` 也可以 ——
交互式时 skit 会询问是否作为提示词添加（默认是）；非交互式时它从不猜测，
因此请传入 `--prompt`。你也可以用 `skit add --prompt` 从零起草一个。

## 占位符 [#placeholders]

最多 30 个检测到的 `{{占位符}}` 会成为输入字段。当检测数量超过 30 时，
默认不管理任何一个。这条规则可以防止代码示例变成变量。
请使用条目设置或 `skit params --add NAME` 来管理你想要的字段。
受管字段获得完整的预设、上次使用值与 `--set` 体验。

没有需要学习的转义序列：任何不是你所管理的占位符的内容 ——
包括未受管的 `{{洞}}` —— 都逐字节原样传给代理。
按提示词的开关（`--no-interpolate`，或条目设置中的 true/false 字段）
可以完全关闭插入。

## 运行器 [#runners]

**运行器**是接收渲染后提示词的代理 CLI。有八个预先配置好 ——
首次使用时写入，之后由你编辑：

| 运行器 | 命令 |
| --- | --- |
| `claude` | `claude -- {{prompt}}` |
| `codex` | `codex -- {{prompt}}` |
| `opencode` | `opencode --prompt={{prompt}}` |
| `amp` | `amp -x {{prompt}}` |
| `antigravity` | `agy --prompt-interactive {{prompt}}` |
| `copilot` | `copilot --interactive={{prompt}}` |
| `cursor` | `cursor-agent -- agent {{prompt}}` |
| `pi` | `pi {{prompt}}` |

在那些 CLI 支持的地方，`--` / `=` 绑定形式是有意选择的：
它们可以防止以 `--help` 或 `--model` 开头的提示词被解析成选项。
Cursor 固定的 `agent` 子命令同样可以防止像 `status` 这样的开头提示词
被派发成另一个 Cursor 命令。所有这些都会用提示词作为开场消息打开代理的
交互会话 —— 除了 amp，它没有这种模式，因此使用官方的 `amp -x`
一次性执行提示词并返回。

Pi 的位置参数解析器既没有选项结束分隔符，也没有绑定的提示词选项。
如果渲染后的提示词以 `-` 或 `@` 开头，或者恰好等于 Pi 的某个包命令，
skit 会警告并在启动前加上一个换行符。这个非无损的回退方案让 Pi 保持交互模式，
并防止它把提示词当作选项、附件或包操作。同样的警告与回退也适用于
非交互式的 skit 运行。

用下面的方式注册其他运行器：

```bash
skit runner add mycli -- mycli run {{prompt}}
```

模板规则：每个词是一个 argv 参数（任何地方都不经过 shell）；
必须正好有一个参数是 `{{prompt}}`；它不能是第一个参数（那是可执行文件）；
不允许其他 `{{洞}}`；单花括号文本是字面量。

运行器如何被选择：

- **交互式运行**：在启动菜单中选择，并以你上次的选择预填。
  你没有改动的固定值不算一次选择。
- **非交互式运行**：`--runner` 胜过条目的固定值；两者都没有时，
  运行以退出码 126 失败。这里有意没有全局默认值，也没有排序 ——
  运行器改变的是*结果*。上次的选择只用于预填交互式表单，
  它从不解析 `--no-input` 的运行。
- 每次运行的代理选项跟在 `--` 之后：`skit run review -- --model opus`。
  这些尾部参数像任何条目一样被记住 —— 参见
  [参数与值](/zh-CN/docs/parameters#what-gets-remembered)。

## 传递 [#delivery]

运行一个提示词会渲染文本，并用它调用所选运行器已配置的 argv 命令。
渲染后的提示词作为单个进程参数传递 —— 中间没有 shell，
因此文本中的任何内容都不会被 shell 解释。

过大的提示词在启动前就会被拒绝，并给出说明测得大小的清晰错误（退出码 125），
而不是原始的操作系统失败：组装后的命令行上限在 Windows 上是 60,000 个
UTF-16 单元，在 POSIX 上是 100,000 字节 —— 中日韩文本按字节计，而不是字符。
渲染后的文本中出现 NUL 字节同样会被拒绝。

## 不是敏感值通道 [#not-a-secrets-channel]

渲染后的文本包含什么，就会进入接收代理自己的会话日志。
不要把敏感值放进提示词 —— 这里没有任何传递机制会假装不是这样。
