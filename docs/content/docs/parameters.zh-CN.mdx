## 值从哪里来 [#where-a-value-comes-from]

最高者胜出：

1. 本次运行的 `--set NAME=VALUE`（或你在启动菜单中输入的内容）
2. 应用的预设（`-p NAME`）
3. 上次使用的值
4. 参数声明的默认值

如果一个必填参数在任何来源都没有值，非交互运行会以退出码 125 失败 ——
skit 从不猜测。

## 默认值来自脚本 [#defaults-come-from-the-script]

启动菜单用脚本**当前**的默认值预填每个参数。skit 每次都重新读取源文件，
因此在脚本中修改一个常量会立刻更新菜单。`skit params --resync` 会把刷新后的
定义写回去。清除覆盖值即可使用脚本当前的值。

当 CLI 解析器的默认值指向一个常量时
（argparse/click/typer/`parseArgs` 中的 `default=DEFAULT_HOST`），
skit 会把它解析为字面量 —— 但只有当这个名称在文件中恰好绑定一次，
并且看起来不像敏感值时才会这样做。看起来像敏感值的常量，
其字面量从不离开脚本自身的文本。

## 空就是空 [#empty-means-empty]

字段到达时已用默认值预填，因此清空一个字段是有意为之：
它会通过注入、环境变量或选项传递一个真正的空字符串（`''`）。
`--set NAME=` 在 CLI 上表达同样的意思。对于空值不能作为取值的类型 ——
`int`、`float`、`bool`、`choice`、敏感值，以及没有默认值的参数 ——
空仍然表示“未设置”。代理可以通过 `skit show --json` 中每个字段的
`delivers_empty` 区分这两种情况。

## 记住了什么 [#what-gets-remembered]

- **上次使用的值**会在下次运行时预填回来。等于声明默认值的提交值*不会*被存储 ——
  这样脚本默认值未来的更改就不会被旧的一次运行掩盖。要有意固定某个值，
  请使用预设：预设逐字存储该次运行，包括被清空的字段。
- **`--` 尾部参数**（`--` 之后的额外参数）按条目记住，并在下一次不带参数的运行中
  重放，同时在标准错误上给出说明。`--forget-args` 清除它；`--raw` 从不重放它。
- **运行历史**：每个条目的状态文件记录上一次运行的时间、退出码与准确的值。
- 所有这些都保存在 skit 的状态目录中（每个条目一个 TOML 文件）—— 参见
  [环境变量](/zh-CN/docs/environment)了解它在哪里，以及如何移动它。
  删除条目会同时删除它的状态。

## 值记号 [#value-tokens]

记号可用于任何启动菜单的值、`--set` 的值与预设的值。它们按写下的样子存储，
并在每次运行时重新展开 —— 写着 `{cwd}` 的预设永远表示“我在哪里运行它”。

| 记号 | 展开为 |
| --- | --- |
| `{cwd}` | 调用时的工作目录 |
| `{today}` | 日期，`YYYY-MM-DD` |
| `{now}` | 时间，`HH-MM-SS` |
| `{env:NAME}` | 环境变量 `NAME` —— 变量缺失是硬错误（退出码 125），而不是静默的空值 |
| 开头的 `~` | 主目录 |

只有这些名称会展开；任何其他 `{…}` 文本原样通过，而 `{{` / `}}` 转义为字面花括号。
例外是提示词与命令的占位符值，其中 `{{` 与 `}}` 逐字节原样通过
（具名记号仍然展开）。

多值参数还会对每一段做 shell 拆分并展开通配符（递归，以调用目录为根）。
来自 CLI 的额外 `-- ARGS` **不会**再次记号化或展开通配符 ——
它们已经经过你的 shell。

## 敏感值 [#secrets]

标记为敏感的参数从不被保存：不在上次使用值中，不在预设中，也不在运行历史中 ——
在每次状态写入时以结构方式强制执行，并且当你把一个已使用的参数标记为敏感时
会追溯清除。敏感值在 `--dry-run` 与命令显示中被遮蔽（`•••`）。
若要完全避免输入它们，`--env-source NAME=ENVVAR` 会在运行时从环境变量读取该值 ——
只有变量的*名称*会被存储。

该值仍然会到达正在运行的进程，而且提示词不是敏感值通道：
渲染后的提示词会进入接收代理自己的会话日志。
